# Checks and limits

These checks concern the portable repository and prepared first integration.
They do not establish that the work Cursor account has loaded this harness.

## Preserved source and active dependencies

The complete 160-file package is preserved at upstream commit
`23e4138daa01c42d4969f7a5465f82704e64f798`, version 0.15.6. An independent
Git-blob comparison caught CRLF conversion during initial extraction. Each file
was restored from its raw pinned Git blob and the snapshot hashes regenerated.
The raw source has a Git attribute preventing subsequent text conversion.

The ledger covers 49 public skills/principles, 23 playbooks, two upstream agents
and three dormant Benny skills. The installer activates only seven adapted
skills and one adapted investigator. The four new routing/investigation/adoption
skills passed Skill Creator's quick validator. The portable stdlib validator
checks the complete snapshot, inventory, profiles, frontmatter and relative links.
It is a structural check, not a complete YAML or behavioral validator.

## Behavioral trials

A bounded Node fixture was investigated using the new router and walkthrough.
The investigator traced the active entry point, found different documented and
actual defaults, identified unreachable legacy code, and ran existing entry-point,
test and boundary checks. The two existing Node tests passed. No fix was applied.

A second fixture had an existing project walkthrough skill and AGENTS.md route.
The adapted router used that recipe first. It traced the implementation and ran
the existing checks successfully. This establishes coexistence in a controlled
case; it is not an audit of the unknown work harness.

The parent applied the adapted swarm contract to an independent source/profile
audit. That audit found the provenance and custom-path issues described here.
The parent inspected and corrected them. This is a real scoped audit use, not
a benchmark of multi-agent speed or a live Cursor worker activation test.

Earlier trials applied automate-me to invented excerpts and a starter mode. It
retained supported preferences, kept project commands out of global policy and
rejected embedded transcript instructions and invented permanent agent counts.
No real full-history mining was performed. The mode remains a seed from this
conversation.

Earlier source audits assessed the entire library. A probe ran the actual
upstream plan checker: its filled ten-lane template passed without executed
checks or screenshots; removing lane ten failed. This measures structural
enforcement, not task correctness. The full upstream Bun suite was not run.

## Installers

PowerShell and the bundled Git POSIX shell on Windows passed resource copying,
unchanged reinstall, customized supporting-resource preservation with exit 2,
explicit replacement with exact backups, and retention of unrelated skills,
rules, agents and extra resources. Dry-run wrote no files. POSIX installation
has not been exercised on a separate Linux or macOS computer.

The independent audit found that unrelated custom skill and agent roots could
break the shared relative contract. Both installers now reject such layouts
before writing. The supported layout uses adjacent `skills` and `agents` roots.
The portable installed-file check compares all selected supporting resources;
it also compares the project rule when present. It cannot check discovery.

## Remaining work-side checks

- Locate and compare the actual existing work harness.
- Confirm skill and agent discovery in a fresh Cursor chat.
- Confirm the User Rule or namespaced project rule applies as intended.
- Exercise a real work task and inspect the evidence and any conflict.
- Later, supply selected accessible history and review the personalized draft.

No work-machine installation, User Rule change, real work-history mining,
employer connector access or live PR fleet has been performed. Source files and
instructions do not create models, subagent tools or permissions.

The repository is published at [gcloudan/pstack](https://github.com/gcloudan/pstack).
The SSH key remains outside the repository and transfer bundle. The repository
contains public source, adaptations and reviews, not surrounding audit fixtures
or private transcript state.
