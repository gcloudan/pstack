# Delivery checks and limits

Prepared 3 October 2026. Checks apply to this kit, not to an installed work
Cursor account. The original pstack files were not modified.

## Behavior check

A separate agent applied the builder to three invented excerpts and the
existing starter mode. It proposed a short comparison table preference and a
concise status preference, preserved uncontradicted starter rules, kept a
project-only verification command outside global preferences, and rejected
an assistant-invented agent count, a one-task long explanation, a one-task
no-edit constraint as permanent policy, and an embedded instruction to publish
transcripts. It did not edit files or execute that exported instruction.

It disclosed missing state and limited source coverage instead of claiming
full-history processing. It identified unclear state/activation paths; the
final builder now states a default private state path and Cursor activation
instructions. Those clarifications were inspected after the trial; the full
trial was not repeated.

This is a small synthetic forward check, not a productivity benchmark or a
test of account transcript access.

## Portable files

The two ordinary skills pass Codex Skill Creator's quick validator. Its local
validator rejects Cursor's documented `disable-model-invocation` property,
so the builder is checked with YAML parsing and the Cursor frontmatter schema
instead of removing a valid explicit-invocation setting. All retained skill
and documentation links are checked locally.

## Installer

The PowerShell installer was exercised in a temporary workspace directory,
not the user's global Cursor skills. First install copied all three files;
an unchanged rerun reported all three current. Differing-copy preservation,
explicit replacement and backup checks are recorded in the final delivery
status below. The shell version has equivalent copying behavior, but runtime
validation is pending availability of a usable local POSIX shell.

## Pending work-side checks

- Work Cursor discovers all three installed skills in a fresh chat.
- The User Rule loads work-mode across the intended projects.
- Selected real exported histories are accessible and authorized to use.
- The resulting personalized draft represents the user's preferences.
- A real work task benefits from the accepted mode.

No real work histories were mined. No User Rule was changed on this machine.
Subagent tools, model access and transcript availability remain capabilities
of the actual execution environment.
